# 서울 지하철을 만들자 — v20 이후 개발계획

핵심 반복: **노선 설계 → 승객 발생 → 문제 발견 → 개선 → 수익과 도시 성장 → 재설계**

## 원칙

- 실제 서울·수도권 역 자리와 수요는 유지한다.
- 역 이름은 기본 이름을 쓰거나 플레이어가 바꿀 수 있다.
- 노선 연결, 순서, 환승 구조, 이름과 색은 플레이어가 정한다.
- 지도는 공식 노선도식 모양을 유지한다. 실제 거리와 화면 선 길이는 분리한다.
- 자동 기능은 편의를 주되, 서로 다른 전략적 선택을 없애지 않는다.

## 단계

1. **실제 거리 분리 (v20, 완료)**
   - 공식 노선도 좌표는 화면에만 사용한다.
   - 기존 역간 자료는 그대로 쓰고, 새 연결은 위·경도 직선거리로 계산한다.
   - 거리로 공사비와 운행시간을 계산한다.

2. **내 노선 편집**
   - 노선 이름·색 변경
   - 양 끝 연장에 더해 중간역 삽입
   - 끝역 단축 및 폐선
   - 수정 전에 비용과 승객 변화 예상 표시

3. **환승과 병목**
   - 환승역 대합실 용량, 환승 거리와 시간
   - 환승 혼잡 표시
   - 환승통로·대합실 확장 공사

4. **운행계통**
   - 완행·급행
   - 구간 운행과 지선 셔틀
   - 같은 선로를 공유하는 운행계통

5. **역 성장**
   - 접근성 개선에 따른 장기 수요 증가
   - 주거·업무·상업 성격 변화
   - 역 등급과 상가 가치 변화

6. **경영과 사건**
   - 대출, 보조금, 공공성 목표
   - 공사 지연, 민원, 재개발, 축제
   - 무조건 정답이 아닌 위험·보상 선택지

7. **정보 화면과 균형**
   - 노선 수정 전후 예상 승객·시간·수익 비교
   - 승객이 선택한 경로와 못 탄 이유 표시
   - 여러 시작 자금과 난이도, 장기 목표

각 단계는 구현 후 저장·모바일·장기 시뮬레이션 회귀 테스트를 통과한 뒤 다음 단계로 간다.
